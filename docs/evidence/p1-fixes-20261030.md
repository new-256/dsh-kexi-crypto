## 二、P1-1：门禁随机红绿的根因与三分类改造

### 2.1 根因（体检 §P1-1 已定性，本轮复现确认）

旧 `_NET_SIG` 正则覆盖 `HTTP Error (?:429|5\d\d)`，**恰好漏掉本机两种真实受限形态**
`451`（Binance）与 `403`（Bybit）。于是同一份代码的归类只由"当时网络返回什么"决定：

| 运行形态 | 观测者 | 根异常 | 旧归类 | 旧结果 |
|---|---|---|---|---|
| ① 451 | 体检团 01:27 / 01:47 两次 | `RuntimeError: HTTP Error 451:` | 代码堆栈 → FAIL | **10/11 红** |
| ② SSL 中断 | 体检团 ~01:43 | `<urlopen error [SSL: …]>` | 网络 → INFO | **11/11 绿** |
| ③ **无参挂起**（本轮新增样本） | 修复团 02:00 / 02:05 两次 | 25s 超时（`backtest/new_listing/news_watch/screener/wallet_watch`） | INFO 挂起 | **11/11 绿** |

即：**同一份代码、同一台机器、同一小时内三种结果**。形态③是本轮补上的第三个实证样本
（体检报告只抽到 ①②）：451 的时段是红，SSL 的时段是绿，而"网络慢到挂起"的时段同样是绿——
后者甚至比 451 更危险，因为它连"网络受限"都不会说出口。

### 2.2 改造后（三分类 + 阈值 + 落盘记录）

`scripts/test-scripts-smoke.py`：

1. **业务异常白名单优先判定** `_BIZ_SIG`（TypeError / KeyError / AttributeError / NameError /
   UnboundLocalError / ImportError / ModuleNotFoundError / SyntaxError / IndentationError /
   TabError / IndexError / ZeroDivisionError / RecursionError / NotImplementedError /
   AssertionError / StopIteration）→ **永远 FAIL**，即使异常串里同时出现网络字样。
   刻意**不收** `ValueError`/`OSError`：它们会从解析与 IO 层冒出，拿来当业务铁证会把真网络失败误判成红。
2. **受限网络签名** `_NET_SIG` 补齐 `HTTP Error (?:451|403|429|5\d\d)` 及
   `urlopen error` / `[SSL:` / `Connection(Reset|Refused|Aborted)` / `timed out` /
   `getaddrinfo failed` / `Name or service not known` / `Max retries exceeded` → **SKIP**。
3. **SKIP 显式打印**：`SKIP  受限网络 → new_listing.py（HTTP 451）`（脚本名 + 具体状态码/原因）。
4. **SKIP 计入汇总行**（禁止静默跳过）：
   `test-scripts-smoke: N/N 通过, M 项 SKIP（受限网络：a.py → HTTP 451, …）`，
   挂起同样进汇总：`, K 项 INFO 无参挂起（未验证：…）`。
5. **⑦ 未验证率阈值 20%**：`(SKIP + 挂起) / 全脚本数 > 20%` → 整步 FAIL。
   挂起**不享受** SKIP 豁免（它连"缺参应快速报错"都没证明），但也不单独判红——
   计入同一个"未验证"分母，避免"网络受限"变成整体不计数。
6. **⑧ 连续 SKIP 检测**：同一脚本连续 3 次运行都 SKIP → 整步 FAIL。计数落盘
   `docs/evidence/smoke-skip-streak.json`（可用 `KEXI_SMOKE_STREAK_FILE` 改路径）；
   该文件损坏/不可写 → **判 FAIL 并打印原因**（保护不允许静默失效）。

```js
const lease = await ap.acquireScope(id)          // ① 钉住这一次 revision
const scope = createScope(ctx, {})              // ② 必须用**全新 key**：拿 lease.key 会自环
const mounted = await ap.mount(scope.ctx, id)   // ③ 真挂载；根 ctx 直调会抛 requires a scoped context
```

- 坑1：`acquireScope` 返回的 `key` 是**预设自己的作用域身份**，拿它建新作用域会立刻
  `dsh-scope: scope parent link would form a cycle`（旧代码"不 mount"正是绕开了这一切）。
- 坑2：`serviceFor(agent,'tools')` 要的是"带 ctx 的 agent 句柄"，且预设组内并没有独立
  `tools` 服务——正确姿势是全局 `ctx.get('tools')` + `tools.view(scopeOf(agentCtx))`，
  靠 `bindScopeParent` 的父链看到预设那一层。
- 为什么**不**断言 `subagent` 出现在站立工具面：`dsh-tool-subagent` 一旦配置了
  `allowedAgentPresets`，apply() 就改成**按 Agent 发布**（上游 `index.js` L536-539 的门禁：
  `if (!modelSelectionCapable && (!presets.configured || session !== undefined || compositionScope === undefined)) install(ctx)`）。
  站立作用域里没有它是上游设计，不是没挂载。改由 `compositionInventory()`
  的**挂载树行**（来自真实 `mount.tree`，不是 YAML 文本）断言"委派行恰好 1 行且 ACTIVE"，
  避免这条变成假红。

退出码语义：`0` 通过 / `1` 断言失败 / `2` 环境不可用。旧实现的两个缺陷已修：
`process.exitCode = 2` 的死赋值（被 `process.exit(code)` 覆盖）、以及外层 catch 把
"预设坏了"（断言失败）一律压成 2（现在 `code = failures.length ? 1 : 2`）。
