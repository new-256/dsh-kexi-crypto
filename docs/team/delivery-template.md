# 最终交付说明 · 模板（delivery-template.md）

> **用法**：证据齐了之后复制本文件生成正式交付说明（建议命名 `docs/delivery-v<版本>.md`），
> 逐块把 `<…>` 占位替换成实测值。**本文件本身不承载任何结论**，不得直接当交付件发出。
>
> **五条铁律（违反其一，整份交付说明作废）**
>
> 1. **不得编造**：命令、输出摘要、哈希、字节数、时间，一个都不许凭印象填。
> 2. **拿不到就写 `UNVERIFIED`**，并在该块下方写明「缺什么证据 / 谁负责 / 何时补」。
>    空白不算，猜更不算；把 UNVERIFIED 写成 PASS 是伪造。
> 3. **每个 PASS 必须三件套**：`命令` + `输出摘要` + `日志路径`。缺一件即 `UNVERIFIED`，不计入通过数。
> 4. **时间一律互联网北京时间**，写明来源与偏移；来源不可用就写「来源不可用」，不得用本机时间顶替。
> 5. **哈希与字节数必须对本机最终文件实测**，不得从旧日志里抄（日志里的哈希可能是更早产物的）。
