# token-budget-discipline

研判团极简通信与 Token 预算纪律守则：以文件为介质，以摘要为传导，杜绝上下文爆炸。

## 一、文件交接铁律（零冗余落盘）

1. **大数据一律落盘**：所有原始 K 线、技术指标明细、全市场扫描清单一律写入 `<工作区>/kexi_out/` 目录。
2. **只传路径与摘要**：跨成员委派与回传时，**严禁将大 JSON 或全量数据表格贴在对话上下文中**。消息体仅传递文件路径（如 `kexi_out/btc_1d.json`）与 1~2 行紧凑结论。
3. **明细截断留看板**：对话中展示历史明细表格最多只取最近 10 根已收盘 bar 或关键档位；全量数据保留在文件中供 `dashboard.py` 生成的可视化看板渲染。

## 二、结果引用与摘要规约

1. **紧凑摘要引用**：引用研判结果时，必须使用 `compact_report.py` 生成的极简文本摘要（约 700 字符）或 DSH `kexi` 工具返回的 digest。
2. **严禁原始 JSON 回灌**：严禁在 Agent 对话中回帖包含几百行字段的未压缩 `report.json`，违者将迅速耗尽会话上下文窗口。

## 三、命令聚合（长流水线优先）

1. **单命合流**：能使用 `kexi_run` 单一工具完成“取数 + 指标 + 报告 + 校验 + 看板”时，禁止拆分成 5 条独立的 shell 命令与多轮往返。
2. **批量执行**：必须执行 CLI 命令时，尽量一次性串联脚本执行，减少多次启动子进程与冗余交互输出。

## 四、成员字数预算分配

各成员单次产出必须控制在明确的字数预算内，精炼表达、直奔主题：

| 成员角色 | 责任领域 | 单次字数上限 | 表达与交付准则 |
|---|---|---|---|
| **数脉** (市场数据) | 取数质检与异常 | ≤ 600 字 | 仅列现价、周期、剔除未收盘bar数、停更天数与异常说明，禁止罗列全量K线 |
| **指北** (技术指标) | 指标计算与关键位 | ≤ 700 字 | 核心列出排列状态、MACD/RSI状态、ATR、关键支撑阻力各 2~3 个 |
| **望潮** (趋势预判) | 方向研判与三情景 | ≤ 600 字 | 给出方向/强度/置信度、三情景概率与证伪条件，拒绝长篇文学修辞 |
| **守拙** (风险评估) | 风险等级与预警 | ≤ 500 字 | 给出风险等级、核心依据与 3~6 条干货风险警示，直截了当 |
| **K析** (主理人) | 终稿汇编 | 按模板排版 | 采用 `report-template.md` 五段式汇编；引用成员产出时不重复复制相同表格 |

## 五、异步等待与轮询纪律

1. **事件驱动通知**：对于耗时较长的数据抓取或模型调用，必须依赖系统的异步事件通知自动唤醒。
2. **严禁盲目轮询**：严禁在对话中使用 `sleep` + 循环查询状态命令，避免无谓消耗轮次与产生空转 Token。
