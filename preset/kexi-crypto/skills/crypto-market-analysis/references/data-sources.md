# 数据源参考：虚拟币行情 API

## 0. 统一口径（全包强制，先看这一节）

### 0.1 只用"最后一根已收盘 K 线"
所有交易所日线的最后一根在盘中**尚未走完**：close 是瞬时价、volume 是部分量。
直接参与 MA/MACD/RSI/量比/ATR/打分会造成系统性失真。

实测（DOGE，2026-09-27 18:54 抓取，当根仅走完 45.4%）：

| 指标 | 含未收盘 bar | 剔除后 | 偏差 |
|------|-------------|--------|------|
| MA10 | 0.094469 | 0.092872 | 偏高 1.72% |
| RSI6 | 62.61 | 60.50 | 偏高 2.11 |
| MACD HIST | 0.001865 | 0.002101 | 偏低 11.2% |
| 量比 | 0.3221 | 0.5092（按已过时段折算） | **低估 58%** |

→ 全包通过 `scripts/kline_utils.py::drop_open_bar` 统一收口；各脚本取数后**必须先过滤**。
判定规则通用（各所 ts 均为开盘/桶起始时间）：`ts + 周期 <= now` 即已收盘。

### 0.2 价格精度自适应
**禁止固定 `round(x, 2)` / `round(x, 4)`**：PEPE（4.39e-06）等低价币会被抹成 `0.0`，
导致 close / MA / MACD 整体报废。统一用 `kline_utils.rn`。

### 0.3 周期必须校验，不得默认信任请求参数
用时间戳中位差推断真实周期（`kline_utils.detect_step_ms`），与请求不一致时必须在
`warnings` 与报告中显著标注。降级源尤其容易返回不同粒度。

## 1. Binance 公开 API（首选，无需密钥）

| 用途 | 端点 |
|------|------|
| K 线 | `GET https://api.binance.com/api/v3/klines?symbol=BTCUSDT&interval=1d&limit=120` |
| 24h 实时快照 | `GET https://api.binance.com/api/v3/ticker/24hr?symbol=BTCUSDT` |

- interval 支持：`1m 5m 15m 1h 4h 1d 1w`（本专家默认 `1d`，辅以 `4h` 验证）
- K 线返回数组：`[开盘时间ms, 开, 高, 低, 收, 成交量, ...]`（字符串数值，需转 float）
- 限流：按权重计，klines limit≤100 权重为 1；普通使用远低于上限
- 常见错误：`400` 参数错误（检查 symbol/interval）；`418/429` 被限流（退避重试）；部分地区网络不可达（切 CoinGecko）
- 备选域名：`api1.binance.com` ~ `api4.binance.com`、`api.binance.us`（注意交易对差异）

## 2. CoinGecko 公开 API（降级源，无需密钥）

| 用途 | 端点 |
|------|------|
| OHLC | `GET https://api.coingecko.com/api/v3/coins/bitcoin/ohlc?vs_currency=usd&days=120` |
| 实时价 | `GET https://api.coingecko.com/api/v3/simple/price?ids=bitcoin&vs_currencies=usd&include_24hr_change=true&include_24hr_vol=true` |

- OHLC 返回 `[ts, o, h, l, c]`，**无成交量**——量价分析不可用，须在报告中注明
- ⚠️ **`days` 只接受枚举值 `1, 7, 14, 30, 90, 180, 365, max`**，传其它值一律 **HTTP 400**
  （早期版本用 `days=120`，导致日线降级路径 100% 失败）
- ⚠️ **CoinGecko 免费档没有真正的 1 天粒度**：粒度由 days 决定，1-2 天≈30分钟，
  3-30 天≈4小时，**31 天以上≈4天**。因此"日线 120 根"在 CoinGecko 上**不可能拿到**：
  合法取值 `days=90` 只能返回约 23 根 **4 天** bar，且 MA60 / MACD（需 ≥35 根）不可算。
  → 降级后必须按 `interval_actual` 标注真实周期，**不得仍称"日线"**，并显著降置信度；
  日线分析应以 Binance 为唯一主源
- 免费档限流约 10-30 次/分钟，频繁调用会 429（实测连续 3 次调用即触发）；退避时间 1/2/4 秒偏短
- symbol → coin id 映射见 `fetch_klines.py` 的 `CG_IDS`，未覆盖币种需先查 `/coins/list`

## 3. 异常场景处理规范

### 数据获取失败
1. 同一源指数退避重试 3 次（1s/2s/4s）
2. 切换到另一数据源重试
3. 均失败：输出 error 字段，报告标注"数据缺失"，列明已尝试路径与失败原因
4. **铁律：严禁凭记忆/训练数据编造任何价格、K 线或指标数值**

### 数据质量问题
- 重复时间戳：去重并在 warnings 记录
- 区间缺口：标注缺失范围，缺口 >20% 时结论降置信度
- OHLC 关系不一致（如 high<low）：标记异常根，不静默修正

### 极端波动（单根 ±10%+ / 插针）
- 脚本自动在 warnings 中列出极端 K 线（时间 + 幅度）
- 分析侧必须：
  - 提示"均线/MACD 等滞后性指标在极端行情中准确性显著下降"
  - RSI 超买超卖阈值参考意义降低（强势趋势中可长时间超买）
  - 趋势研判以关键位得失与量价为主，弱化精确点位预判
  - 风险等级原则上不低于"高"；闪崩/插针 ±15%+ 直接评"极高"

### 样本不足
- <60 根：MA60、MACD 信号标注"样本不足，仅供参考"
- <30 根：RSI14 不可靠，仅提供数据概览，不出趋势结论
