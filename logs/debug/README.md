# logs/debug · 调试与取证日志

**用途**：故障现场与排障过程——怎么复现、原始报错全文、定位到的代码位置、根因结论、
以及「确认不是本项目的问题」的判定依据。**结论必须落成文档，不能只留在终端回滚缓冲里。**

**文件命名**：`YYYYMMDD-HHMM-主题.md`（一次排障一个文件）。

**每份排障文档至少写清五件事**

1. **复现步骤**：命令或操作序列，照抄可跑。
2. **原始报错全文**：不截断、不摘要（用户规则 28）。
3. **定位**：文件路径 + 行号，必要时贴最小区块。
4. **根因**：是设计缺陷、实现缺陷、还是环境/上游问题；若是外部因素，给出排除证据。
5. **处置**：已修（指向修复文档）/ 待修（指向任务编号）/ 不修（给出理由）。

**临时产物纪律**

- 一次性实测产物放 `.kexi-test-tmp/`（已被 `.gitignore` 忽略），**不入库**。
- 值得长期留存的原始输出（测试日志、监控 CSV）转存 `logs/build/`，不要留在本目录。

**本目录已有的机器产物**

排障脚本（如 `run-all-tests.ps1`、`_hw-monitor.ps1`）会直接往这里写
`*.log` / `*.csv` / `.current-ts`（当前批次时间戳）。这些是脚本自动生成的，
命名由脚本决定，**不要手工改名**，否则脚本续跑会对不上批次。

**入库**：是（一次性产物除外）。

**不放什么**：方案设计 → `logs/arch/`；正式门禁结论 → `logs/build/`。
