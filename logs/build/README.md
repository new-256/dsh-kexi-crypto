# logs/build · 编译与门禁日志

**用途**：记录「跑过了没有、结果是什么」这类可机械复核的证据——语法检查、门禁脚本输出、
测试套件报告、打包校验、硬件资源监控采样。

**本目录由回归团主导写入**，执行器为 [`run-gate.ps1`](run-gate.ps1)：
它给任意命令加强制超时 + 同步启动硬件监控 + 全文落盘，并往 `gate-index.jsonl` 追加一条索引记录。

## 一、实际命名约定（以 `run-gate.ps1` 为准，勿手工改名）

同一批次共用同一个时间戳前缀 `<YYYYMMDD-HHMMSS>-<门禁项短名>`：

| 后缀 | 内容 |
|---|---|
| `.out.log` | stdout 全文 |
| `.err.log` | stderr 全文 |
| `.hw.csv` | 该批次硬件监控采样（CPU / 内存 / GPU / 显存） |
| `_tmp/<stamp>-<name>.gate.ps1` | 该批次的子进程包装脚本（排障时看它，别删） |
| `gate-index.jsonl` | 全量批次索引：一行一次执行，含命令、退出码、耗时、日志路径、runId/冻结号 |

另有手写结论文档按 `gate-YYYYMMDD-主题.md` 命名（逐项 PASS/FAIL + 证据路径 + 残余风险）。

## 二、命令怎么跑

```powershell
# 单个门禁项：强制超时 + 硬件监控 + 全文落盘
pwsh -NoProfile -File logs\build\run-gate.ps1 -Name verify -Command "node scripts/verify.mjs" -TimeoutSec 900

# 带 runId / 冻结号的出厂批次
pwsh -NoProfile -File logs\build\run-gate.ps1 -Name runtime -Command "node scripts/test-runtime.mjs" -TimeoutSec 1800 -RunId RUN-20261030-V1923 -Freeze FREEZE-20261030-V1923
```

退出码语义：`0` = 成功；`124` = 超时被强杀；其它 = 命令自身退出码（原样透传，绝不吞掉）。

## 三、硬性纪律

1. **必须设防卡死超时**：超时即强杀**整棵进程树**，并输出卡死位置与最后日志原文（用户规则 12）。
2. **硬件监控必须与测试同步启动**：CSV 落本目录，不得只跑测试不记资源（用户规则 7）。
3. **失败原文全文保留**：不截断、不只留「FAILED」（用户规则 28）。
4. **日志只追加**：需要更正时新开一份并在标题写明更正了哪份，不要覆盖历史。
5. **结论必须可复现**：`gate-*.md` 里每个 FAIL 项都要给出人能照着跑的命令与失败原文。
6. **文件名的批次时间戳是本机时钟**（执行器用 `Get-Date` 生成），仅作批次标识；
   **对外进度与结论里写的北京时间必须取互联网时间接口**，两者不可混用（用户规则 24）。

## 四、`_tmp/` 的处置（Lead 2026-10-30 裁定）

`_tmp/` 里有两类东西，处置方式不同：

| 内容 | 性质 | 处置 |
|---|---|---|
| `<stamp>-<name>.gate.ps1` | **证据**：记录了该批次真实执行的命令与工作目录 | **保留并入库** |
| `a.err`、`race*.txt`、`envprobe.ps1` 等随手试验文件 | 一次性试验 | **出厂前清理**，不做入库 |

**不为其添加 `.gitignore` 忽略规则**，理由（后续同类问题照此办）：
忽略规则会把「一次性试验」**永久合法化**——`_tmp` 一旦被忽略，下次再有人往里扔东西就没人管了；
而「清理」是显式动作，**逐条列入 gate 报告后可被审计**，比静默忽略更可信。
