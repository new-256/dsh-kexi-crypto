# logs/arch · 架构与方案日志

**用途**：记录「为什么这样设计」——方案候选与对比、宿主接口形状取证、影响面清单、
被否决的方案及否决理由。**只写方案，不放代码副本**。

**典型文件**

| 文件 | 内容 |
|---|---|
| `YYYYMMDD-主题.md` | 一次设计决策的完整方案 |
| `YYYYMMDD-主题-取证.md` | 支撑方案成立的接口/行为取证（含文件:行号） |

**命名约定**：`YYYYMMDD-主题.md`（可带版本号，如 `20261030-v1923-delegation-collapse.md`）。
日期时间一律取**互联网北京时间**（见 `LOGS-INDEX.md` 的时间来源约定），禁止用本机系统时间顶替。

**入库**：是。这些是后续接手者与用户复核「当初为什么这么定」的唯一依据。

**不放什么**

- 跑一次就会变的原始输出 → 放 `logs/build/`
- 故障现场与排障过程 → 放 `logs/debug/`
- 最终对外说明 → 放 `docs/`（如 `docs/repair-plan-*.md`）

**与 `docs/` 的分工**：`logs/arch/` 是过程留痕（可能改多轮）；`docs/repair-plan-*.md`
是对外交付件（定稿版）。定稿后结论回写 `docs/`，过程留在本目录。
