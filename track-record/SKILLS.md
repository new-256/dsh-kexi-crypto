# K析研判团 · 技能提炼与迭代手册（Skills Distillation）

> 来源：对 3 次真实运行的战绩建档（`track-record/`），把「哪些做法被验证有效 / 哪些被证伪」
> 固化为**可复用的技能条目**。建档时间 2026-09-29。
> **纪律：本手册只写有档案证据支撑的条目。没有证据的猜测一律标 `[未验证]` 并禁止当结论使用。**

## 0. 使用前提（先读，否则会误用整本手册）

| 限制 | 数值/事实 | 后果 |
|---|---|---|
| 样本量 | **3 次运行 / 31 条预测，其中 Run A 与 Run C 基准相同、重叠 10 币** | **不是独立样本**。任何胜率都不具统计显著性 |
| 视界 | 7 日，均**未到期**（到期 2026-10-04） | 当前全部为中期快照，**禁止宣布胜负** |
| 对照组 | 仅 BTC 基准，**无随机等权对照组** | 只能说「跑没跑过 BTC」，**不能说「选币优于随机」** |
| 信息面 | 3 次运行的消息面/链上资金面**全部缺失** | 无法评估基本面信息的增益 |

> **红线**：在样本 ≥30 轮、且加入随机对照组之前，**禁止把本手册的任何条目当作"已验证的能力"对外表述**。
> 本手册目前的定位是**「有证据的假设清单」**，不是结论。

## 1. 已被证据支持的技能条目

### S1 · 「预测必须显式落盘 entry_price + asof」 ⭐ 最高优先级

**证据**：Run B（PYTH）的原始产物 `member_verdict_pyth.json` / `ov_verdict_pyth.json`
只给了区间与关键位，**没有落盘"作出预测时的现价"**。建档时被迫用当日近似值，
导致收益无法精确计算。

**技能**：任何预测记录必须包含：
```
entry_price, entry_price_asof, horizon_days, baseline_ts_utc
```
**验收**：若事后无法从产物中算出 `ret_pct`，该预测视为**未完成**。

---

### S2 · 「三情景必须落价格区间，否则预测不可证伪」 ⭐ 最高优先级

**证据**：Run C 的第 11-20 位（10 个币，占本轮 50%）**只给了基准概率、没有价格区间**。
导致这 10 条在档案中记为 `hit_zone=unknown`，**事前不可证伪、事后无法评分**。
Run A 的 10 币中只有 ALGO 一个给了完整三情景区间。

**技能**：报告契约强制 —— **每一个标的必须给出 [悲观/基准/乐观] 三个价格区间**。
只有概率没有区间的预测，等于没有预测。

---

### S3 · 「风控结论必须能反向影响名单」 ⭐ 最高价值

**证据**：Run C 的 headline 明确写着「**追高风险大于补涨机会**」，
守拙给了「全池无一低档」的风险定级，望潮给了「中低置信度」——
**但最终仍然交付了 20 个全数看涨的标的**。

**这是三次运行中暴露的最严重流程缺陷**：团队的风险识别是**对的**，
但它**没有进入决策回路**，只是报告末尾的免责式提示。

**技能**：在初筛与最终名单之间**增设一道位置/拥挤度闸门**，让望潮/守拙的高位结论
**直接削减入选数量或调低仓位**，而不是作为事后说明。

> 关联：v1.5.0 已新增 `position.py`（位置扣分）与 `timeframe.py`（多周期）。
> 但**扣分 ≠ 否决**——`hard_pos` 默认关闭。**建议至少对"极高危"档默认开启硬否决。**

---

### S4 · 「风险识别能力 > 排序能力」——应把资源投在风控而非调权重

**证据（Run C 中期数据）**：

| 现象 | 数据 |
|---|---|
| 排名第 1（GRAM，唯一满分 100） | **-2.21%**，跑输 BTC（-1.14%） |
| 排名第 17（HBAR） | **+27.79%**，全池最佳 |
| 被团队"直接回避"的三档极高危 | HBAR +27.79% / PUMP -0.99% / DASH -6.02% |
| 被团队额外标注"实际风险高于排名"的 ONDO | **-12.78%，全池最差** ✅ 判断正确 |

**解读**：综合分与短期收益在本样本中**近乎无关甚至反向**；
而**团队对 ONDO 的定向风险判断被验证正确**。

**技能**：不要在「让综合分更准」上继续投入边际精力。
**应把"望潮/守拙已识别的风险"接到名单生成上**（见 S3）。这比继续调权重更值钱。

> ⚠️ 注意 n=1 的案例不能证明普遍规律（ONDO 正确、GRAM/HBAR 反向都可能是噪声）。
> 本条应作为**假设**，需在后续 ≥10 轮中复验。

---

### S5 · 「必须记录'回避'标的的机会成本」

**证据**：HBAR 被团队标记"极高危、直接回避"，实际录得 **+27.79%**（全池最佳）。
若档案只统计"入选标的"的收益，会**完全看不到这个成本**。

**技能**：`tier` 必须包含 `avoid`，且 **`avoid` 标的必须单独统计"过度规避成本"**。
只统计买入样本 = 选择性偏差。

---

### S6 · 「媒体/新闻面缺失必须显式标记并快速跳过」

**证据**：Run A 报告写明「外部新闻检索通道本次不可用（401／引擎被拦）」；
Run C 因 `kexi_news` schema bug **完全缺席**（见 `docs/evaluation-20coin-run.md` §二·修复 2）。
两次运行都**按纪律没有反复重试**——这一点做对了。

**技能**：检索不可用时**显式写"新闻面缺失"并跳过**，禁止让成员反复尝试后才放弃。
**这是已落地的正确实践，应保持。**

---

### S7 · 「测试夹具必须来自真实捕获的数据」

**证据**：见 `docs/process-retro-v1.4.5.md` §四——v1.4.4/1.4.5 的三个 bug 全部是
"单测用了想当然的字段"造成的，恰好绕过了真实差异。

**技能**：新增任何事件/工具处理，**第一步先抓一条真实样本固化为 fixture**。

## 2. 被证伪的假设（历史猜测，档案不支持）

| # | 曾经的猜测 | 档案证据 | 结论 |
|---|---|---|---|
| F1 | 「splice（团队消息重写）是缓存冷启动元凶」 | 20 币运行 splice 高频发生（lead 17 次、数脉 14 次）**却未破坏命中率（95.4%）** | ❌ **已证伪**，可从候选原因划掉 |
| F2 | 「历史低命中是插件层缓存设计问题」 | 命中率从 5% 跳到 95% 的**唯一变量是 provider 换到支持 prompt caching 的通道** | ❌ **已证伪**；插件层无需自建缓存 |
| F3 | 「`latest.json` 未写入导致跨运行产物错挂」 | 深入取证：`latest.json` **写成功了**，只是写进了 DSH 后端安装目录 | ❌ **初稿结论是错的**，真因是 `workspaceRoot()` 解析错误 |
| F4 | 「放量突破加分名不副实是评分权重问题」 | 真因是**只校验收盘站上、完全不看成交量** | ❌ 不是权重问题，是**逻辑缺失**（v1.4.5 已修 `BREAKOUT_VOL_MULT=1.2`） |

> **F3/F4 的共性教训**：**第一次归因往往是错的**。
> 本仓库已两次因"看起来合理的归因"写错报告（20 币评估初稿、放量突破）。
> **技能**：任何根因结论必须有**文件系统/日志实证**，不能靠推理链自洽。

## 4. 迭代路线图（按证据强度排序）

| 优先级 | 动作 | 依据 | 验收标准 |
|---|---|---|---|
| **P0** | 报告契约强制落盘 `entry_price` + `asof` + 三情景区间 | S1, S2 | 事后能从产物直接算出 `ret_pct` 与 `hit_zone` |
| **P0** | 每次运行结束**自动追加一条** `ledger.jsonl` 记录 | S1 | 不再依赖手工建档 |
| **P1** | 位置/拥挤度闸门接入名单生成（极高危默认硬否决） | S3, S4 | 极高危标的不再进入正式名单 |
| **P1** | 加入**随机等权 N 币对照组** + BTC 基准列 | §0 | 能计算超额收益 |
| **P2** | `avoid` 标的单独统计过度规避成本 | S5 | 档案含"回避成本"字段 |
| **P2** | 对 v1.5.0 的位置/多周期维度做**历史回测** | U2 | 量化命中率/回撤改善 |
| **P3** | 单币深研判（如 PYTH）优先于批量筛选 | S2 证据显示单币预测质量最高 | 报告可证伪率 >90% |

## 5. 一句话总结

> 三次运行最有价值的发现不是"哪几个币涨了"，而是：
> **团队识别风险的能力已经被验证（ONDO），但这份能力还没有被接进决策回路（S3）；
> 而预测的可证伪性本身存在系统性缺陷（S2），导致历史战绩无法被可靠评估。**
> 因此下一步的最高价值动作是**修契约、接闸门、加对照**——而不是继续调评分权重。
